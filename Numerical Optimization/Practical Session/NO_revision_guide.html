What's the difference between np.linspace and np.arange? ▼
np.linspace(a, b, n) gives exactly n evenly-spaced values between a and b (inclusive). np.arange(a, b) gives integers from a to b-1, step size 1 by default. Use linspace when you want a smooth curve; use arange for index-like sequences.
When would you use plt.scatter vs plt.plot? ▼
Use plt.scatter for raw data (each point is independent — e.g. one student's marks). Use plt.plot for model lines or any connected sequence (e.g. the line y = 0.1x − 20 on top of the scatter). In Week 1 you combined both: scatter for data, plot for the guessed line.
What problem does Numerical Optimisation actually solve? ▼
It automates the search for optimal parameters (like m and c) that minimise a cost function. In Week 1 you did this manually ("hit and trial"). NO gives you systematic algorithms — like gradient descent — to find these values without guessing.
02
Gradient Descent (1D)
the core algorithm · learning rate · stepping down a curve

The Central Idea

If you're standing on a hill and want to reach the lowest point, look at which way the ground slopes under your feet — then take a step in the opposite direction. Repeat. That's gradient descent.

The Update Rule — memorise this

x_new = x_old − learning_rate × gradient(x_old)

gradient(x) = the derivative of your function at x — tells you the slope.
Minus sign = we go opposite to the slope (downhill).
learning_rate = how big a step to take.

📉
Example 1

f(x) = x²

Gradient = 2x. Starting at x = −7:

slope = 2 * x x = x - 0.05 * slope # each step

Each step moves x closer to 0 (the minimum). You can see the dots "sliding down" the parabola in the plot.

🎯
Example 2

f(x) = (x−3)² + 1

Minimum is at x = 3 (value = 1). Gradient = 2(x−3).

df_dx = 2 * (x - 3) x = x - lr * df_dx

Starting at x = 0.5, with lr = 0.1 and 20 iterations — converges to x ≈ 3.

🐢
Learning rate too small

lr = 0.01

Takes tiny steps. Converges eventually but very slowly. You need many more iterations to reach the minimum. Cost comes down but painfully slowly.

💥
Learning rate too large

lr = 0.5+

Overshoots the minimum. The algorithm bounces around or even diverges — cost goes up instead of down. This is what Week 4 fixes with backtracking.

What happens when slope = 0?

When gradient = 0, the update is x = x - lr × 0 = x — no movement. You've found a stationary point. For convex functions (like x²), this is always the global minimum. For non-convex functions, it could be a local min, local max, or saddle point — this is why convexity matters (Week 3).

// exam-style Q&A — click to reveal
Write the gradient descent update rule and explain each term. ▼
x = x − lr × ∇f(x)

• x — current parameter value
• lr (learning rate) — controls step size (hyperparameter)
• ∇f(x) — gradient (derivative) of the function at current x — tells us direction of steepest ascent
• minus sign — we move opposite to gradient (downhill toward minimum)
For f(x) = (x−5)² + 3, what is the gradient? Where is the minimum? ▼
Gradient = 2(x − 5). Minimum is at x = 5, where f(5) = 3. The gradient is zero there, so GD stops moving.
What effect does the learning rate have on GD convergence? ▼
• Too small → convergence is painfully slow; needs many iterations
• Too large → overshoots minimum; algorithm may diverge (cost increases)
• Just right → fast, stable convergence
This is the core motivation for adaptive methods like backtracking (Week 4).
03
GD on Real Data
convexity · feature normalisation · MSE loss · linear regression
🥣
Key concept

Convex vs Non-Convex

  • Convex (e.g. x², |x|): bowl shape. Any local min = global min. GD is guaranteed to find the best answer.
  • Non-convex (e.g. sin(x), x³−3x): has multiple valleys. GD can get stuck in a local minimum — not the global best.
  • This is why we care about convexity for AI: training a neural net is non-convex. MSE for linear regression is convex ✅
⚖️
Critical pre-step

Feature Normalisation

House sizes are in 1200–2700 range, prices in 45–130. Raw GD would need tiny learning rates or diverge. Normalise first:

sizes_norm = (sizes - sizes.mean()) / sizes.std()

This centres data around 0 with std=1. GD then converges stably with a normal lr like 0.01.

📏
Loss function

Mean Squared Error (MSE)

The function we're minimising — measures how wrong our line is:

MSE = (1/n) × Σ(y_pred − y_actual)²

Squaring: removes negatives, penalises big errors more. As GD updates m and c, MSE should decrease each epoch.

🧮
The gradients

∂MSE/∂m and ∂MSE/∂c

dm = -2 × mean(X × (y - y_pred)) dc = -2 × mean(y - y_pred)

These come from differentiating MSE with respect to m and c. Then update: m = m − lr × dm, c = c − lr × dc.

Full GD Loop Pattern — memorise this structure

01 / INIT
m, c = 0, 0
Start with flat line. Set lr and num_epochs.
02 / PREDICT
y_pred = m*X + c
Current model's predictions.
03 / LOSS
mse = mean((y−y_pred)²)
How wrong are we right now?
04 / GRADIENTS
dm, dc = ...
Partial derivatives of MSE.
05 / UPDATE
m = m − lr*dm
Step opposite to gradient. Repeat from 02.
// exam-style Q&A — click to reveal
Why do we normalise features before gradient descent? ▼
When features have very different scales (e.g. size = 2000, price = 130), the cost function forms elongated "ellipses" in parameter space. GD takes many tiny zigzag steps. Normalising brings all features to the same scale (mean=0, std=1), making the cost surface more circular — GD converges faster and with a larger stable learning rate.
Why is MSE a good loss function for regression? Why square the errors? ▼
1. Squaring removes negatives — otherwise positive and negative errors cancel out
2. Squaring penalises large errors more — a prediction off by 10 contributes 100, not just 10
3. MSE is convex and differentiable — GD is guaranteed to find the global minimum
4. Mean (not sum) makes it independent of dataset size
What are "epochs" and why track MSE across them? ▼
An epoch is one full pass through the training data — one complete round of predict → compute loss → update. You track MSE across epochs to verify the model is actually learning: MSE should decrease and eventually plateau. If MSE increases, your learning rate is too large. If it decreases extremely slowly, it may be too small.
04
LR Problems + Backtracking
divergence · slow convergence · backtracking line search
🚨
Problem A

lr = 0.75 → Divergence

Step size so large that you overshoot the minimum. Each step lands on the other side of the valley, further away. Cost increases instead of decreasing. The algorithm explodes.

Cost: 100 → 10000 → 1e8 ... 💀
🐌
Problem B

lr = 0.001 → Too Slow

Takes tiny steps. Converges, but needs thousands of iterations for simple problems. In deep learning this is computationally unacceptable — you waste GPU time.

Cost: 100 → 99.9 → 99.8 ... 😴
🔍
The Fix

Backtracking Line Search

Instead of a fixed learning rate, start large and shrink until the cost actually goes down. At each step:

  1. Guess a large lr (e.g. 1.0)
  2. Try a step with this lr
  3. If cost decreased → accept the step ✅
  4. If cost increased → lr = lr × shrink_factor, retry 🔁
⚙️
Parameters

Backtracking Config

  • initial_lr = 1.0 — start optimistic
  • shrink_factor = 0.5 — halve on failure
  • iterations = 150 — outer loop
while cost_new >= cost_old: lr = lr * shrink_factor try step again

Backtracking vs Fixed LR — the key insight

Fixed learning rate requires you to know the right lr in advance — which you don't, in practice. Backtracking makes this choice adaptive: it uses a large step when the landscape is smooth (fast progress) and shrinks automatically near steep or tricky regions. This is the foundational idea behind modern optimisers like Adam, RMSProp, etc. — you're essentially learning to tune the algorithm.

Key guarantee: cost ALWAYS decreases (or stays same) per step → No divergence possible with backtracking ✅
// exam-style Q&A — click to reveal
What happens with lr = 0.75 on the house price GD problem? Why? ▼
With lr = 0.75, the update step overshoots the minimum — it jumps past the valley bottom to the other side, where the cost is higher. The next step overshoots again, but even further. This causes divergence: cost grows exponentially and parameters become infinite/NaN. This happens because the step size is larger than the curvature of the cost surface allows.
Describe the backtracking line search algorithm in plain language. ▼
1. Compute current cost
2. Try a step with large initial learning rate
3. Check: did cost go down?
   • Yes → accept the step, move on to next iteration
   • No → shrink lr by shrink_factor (e.g. halve it) and try again
4. Repeat shrinking until cost decreases

This guarantees cost never increases, and uses large steps when safe, small steps when near the minimum.
How does backtracking line search relate to modern optimisers like Adam? ▼
Both solve the same problem: choosing a good step size adaptively rather than using a fixed lr. Backtracking adjusts lr per iteration based on whether cost improved. Adam and RMSProp go further — they maintain a running estimate of gradient magnitudes per parameter, scaling each parameter's lr individually based on historical gradient information. Week 4 is the conceptual foundation for why adaptive lr methods exist.
